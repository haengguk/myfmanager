## 선행 수정

- A: 경기 선수단과 현재 배치가 같은 선수만 수집하던 조건을 계약 약속 범위와 분리했다.
  현재 운영 구단의 유효 FIRST_TEAM 역할 약속(STARTER/RESERVE)은 DEVELOPMENT 배치로
  사라지지 않는다. 원래 DEVELOPMENT 약속, 객관적 계약/등록 부적격, 등록 이후 합류와
  이주 이전 등록 근거 부족은 기존 경계를 따른다. CL 경기는 1군 분모/이행에 포함하지 않는다.
  고정 선발 `selected`만 실제 세트·성장·숙련도·피로를 받는다. 신규 capture부터 적용하며
  기존 binding/receipt/봉인 약속은 재작성하지 않는다. 기존 28일·6 Series·14일 평가·70% 정책 유지.
- B: 현재와 이전 coverage에 `Observation.full`을 공통 사용한다. CL 무출전 연속 시즌은
  1→2→3이며 실제 출전·연도 단절·부분/해외 관찰은 누적하지 않는다. 선수단 변경 시
  이전 연속 횟수도 초기화한다. 이전 봉인 심사와 은퇴 추첨은 다시 실행하지 않는다.
  과거 버그로 저장된 횟수는 소급 복원하지 않고 저장된 카운터를 출발점으로 신규 심사부터
  누적한다. 심사별 관찰 기록은 남지만 당시의 모든 중간 배치 연속성을 재구성하지 않는다.

선행 집중 두 메서드: 2 통과, Gradle 1분 19초. 최초 도구 실행은 JAVA_HOME 부재 및

허용된 Gradle 실행으로 해결했다. 선행 수정만의 전체 회귀는 실행하지 않았다.

## 운영 연결과 정책

`CareerSquadPlanner`는 Career 시장 transaction workspace 안에서 실행된다. 기존
FA/CL/육성/이적의 독립 주간 생성과 매일 최강 선수 재선발 대신 공통 판단을 사용한다.
관리 구단은 제외하며 AI 55개 구단에 적용한다. 활성 LCK만 CL 인원을 함께 보전하고,
해외의 실행되지 않은 경기/출전 불만은 만들지 않는다.

- 정기 판단: 월요일. 마지막 판단 날짜와 구단·포지션 대기 종료일을 저장한다.
- 기존 strength(12개 현재 정수 능력치 합)를 한 번만 비교한다. CA를 중복 가산하지 않는다.
- 포지션에 맞는 숙련도 상위 3개의 평균은 같은 strength의 순서 결정에만 사용한다.
  PA·PA−CA·생성 등급·미래 성장/은퇴 추첨·피로는 평가 입력이 아니다.
- 교체는 strength 차이가 기존 `AI_IMPROVEMENT_POINTS=12`를 초과할 때만 한다.
  동률과 작은 차이는 현재 선발을 유지한다. 실제 공백은 대기 없이 보완한다.
- 동일 구단·포지션 교체/제안 재검토 대기 28일. 영입 실패를 일일 UUID로 재시도하지 않는다.
- 포지션 후보 최대 3명(만료 예정 현 선발의 재계약 후보 1자리 포함). 구단 주간 새 제안은 모든 유형 합계 최대 4건이며 그 중 유료 이적/임대는
  최대 2건. 같은 포지션은 양 선수단 합계 1건이고 진행 중 제안/거래가 있으면 새로 만들지 않는다.
  기존 협상의 수정 라운드는 기존 최대 3회 규칙을 따르며 새 계획 슬롯으로 위장하지 않는다.
- 후보 순서의 재계약 우대는 기존 strength 8점이다. 안전하게 충원된 선수단·포지션은 보유 2명 미만일 때만
  단순 추가 보강을 검토하며, 양 선수단의 필수 인원을 중복으로 계산하지 않는다. FA/재계약은 기존 2년·연봉 수요
  105~125%·계약금 수요의 1/10, 유료 이적 개인 조건은 기존 수요 135%를 재사용한다.
  임대는 기존 28~366일과 급여 분담 50%, 기존 기간/가격/수락 검사를 따른다.
- 만료 전망/협상 창은 기존 60일. 현재 다음 경기 날짜와 계약·확정 이적·임대 종료/반환·
  은퇴 발표 효력일을 검사한다. 존재하지 않는 해외 경기나 다음 시즌 경기 결과를 생성하지 않는다.
- 승격 시 CL 같은 포지션 내부 후보를 사용하며 필요하면 기존 1군 선수와 적법하게 교환 배치한다.
  계약 역할은 그대로이며 강등된 STARTER의 약속도 A에 의해 평가된다. 대체자 없으면 보류한다.
- 현재 기량과 보유 자원의 만료를 기준으로 내부 유지/승격·재계약·FA·이적·임대를 검토한다.
  기존 연봉 수요/이적료/임대료/급여 분담·선수 선호·구단 예산/예약/체불 검사에 연결한다.
  남는 자원은 합법적인 구매 수요와 연결하고, 미갱신은 자연 만료를 이용한다. 조기 해지를
  기본 행동으로 삼거나 보상금을 회피하지 않는다.
- 진행 중 반대 선수단 출전 및 같은 날짜 교차 출전, 활성 국제 등록을 보수적으로 보호한다.
  등록된 국제 자원의 자발적 외부 이동/CL 배치는 대회 종료까지 보류한다. 다음 국제 등록 밖의
  승격 후보를 현재 등록 공백의 해결책으로 계산하지 않는다. 기존 보충등록 경로는 유지한다.

날짜 순서는 이전 날짜 경기 정산 → 이전 날짜 훈련/회복 마감 → 다음 날짜 확정 배정·
임대 반환·계약 만료/은퇴·예약 계약/이적 발효·급여·약속 평가·기존 협상 응답 →
주간 운영 계획/제안 → 공통 선수 결정 → 자격 상실의 긴급 선발/CL 보완 → 관찰이다.
이미 시작한 Series는 저장된 선수/능력치/Draft/checkpoint/receipt를 계속 사용한다.

## 저장과 표시

기존 시장 JSON의 nullable `squadPlanning`에 정책 버전·마지막 검토·대기·최근 결정 1,000건만 추가한다.
별도 테이블이나 과거 계획 이주는 없다. 구형 JSON은 계획 부재로 읽고 다음 정상 운영일부터
도입한다. Calendar 잠금/시장 revision/transaction과 기존 제안 식별·명령 receipt를 재사용한다.
읽기 전용 조회는 계획을 실행하지 않는다. 시즌별 명부/시장 봉인에도 함께 보존되며 새 날짜에
새 계획을 계산한다. 과거 계획의 예약 행동을 자동 재집행하는 큐는 없다.

시장 View에 `squadOperations`를 추가했다. 실제 적용/유지와 협상·동의 대기·보류를 구분한다.
미확정 상대 구단 후보·조건·내부 구매 상한은 새 projection에서 숨긴다. 기존 계약 화면의
`AI 구단 선수단 운영`에서 구단 선택, 현재 선발/육성 배치/60일 만료와 짧은 이력을 볼 수 있다.
사용자 선발·계약·이동을 대신 집행하지 않으며 기존 명령 잠금/오래된 응답 방어를 유지한다.
