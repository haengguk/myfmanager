# Career 출전·약속·만족도와 유료 이적·임대 V1

## 기준과 목적

시작·최종 HEAD는 `dcea3f70e3d9e80b043d35fd2c940e414a5fa636`, 브랜치는 `main`이다. 구현과 검증을 완료했으며 변경은 미커밋 작업 트리에 있다. 기존 `.gitignore` 수정과 사용자 `prompts/`는 별도 변경으로 보존한다. 기존 460명·56개 경쟁 구단·82개 조직, 미확인 소속/역할 충돌/게임 FA 구분 및 directory의 능력치·숙련도·생년월일·현실 계약 자료는 재import하거나 변경하지 않는다.

기존에는 역할이 계약 조건에 기록되지만 실제 출전 약속의 이행 기록은 없었고, 계약 중인 선수를 구단 간 유료로 이동하거나 원계약을 유지한 채 임대할 수 없었다. 이번 확장은 실제 완료 출전 → 합의한 역할의 평가 → 재계약/선수 이동 판단 → 양 구단 금융과 소속 변경을 기존 Career 시장과 Calendar 안에 연결한다. 경기 능력치, Draft/승패 Random, 성장·PA·훈련·피로에는 관여하지 않는다.

## 출전 사실과 약속

`CareerAppearanceStore`는 적법하게 시작한 Series의 고정 5명과 당시 계약·운영 소속·약속을 결속해 기회 스냅샷을 저장한다. 시작/등록/Draft 진입은 출전이 아니다. 검증된 국내 League 또는 Career 대회 completion을 실제 적용할 때 완료 receipt, fixture, 실제 Series ID, 당시 팀·포지션·playerId, 실제 완료 세트 수를 한 번 반영한다. Player/Auto 공통 완료 경로다.

주전 비율의 단위는 **Series**다. BO3/BO5의 실제 세트 수는 별도 기록한다. 완료되지 않았거나 반려된 결과는 분모도 늘리지 않는다. 완료가 늦더라도 시작 당시 약속 ID에 반영하므로 거래 이후 최신 팀에 과거 출전을 귀속하지 않는다. 이미 적용한 receipt는 다시 반영하지 않는다.

벤치/1군 미선발/구단의 임의 미등록·강등은 유효 계약의 기회를 제거하지 않는다. 국제대회는 등록 날짜와 고정 후보 집합을 보존한다. 등록 후 객관적으로 합류한 미등록 선수는 제외하고, 같은 구단 재계약의 연속된 약속을 새 합류로 오인하지 않는다. 적법한 고정 출전자와 등록된 선수는 실제 자격 근거를 사용한다. 이주 전 등록의 근거가 없는 비선발자는 `PRE_MIGRATION_REGISTRATION_EVIDENCE_UNKNOWN`이다. 이전에 시작해 캡처가 없는 경기는 과거 분모를 추측하지 않는다.

`CareerManagementPolicy`의 초기 정책은 다음과 같다.

| 항목 | V1 정책 |
| --- | --- |
| 관찰 | 28일, 출전 평가 최소 6 Series |
| 평가 주기 | Calendar 14일 간격 |
| 주전 | 누적 평가 가능 Series 중 선발 70% 이상 |
| 후보 | 최소 선발 비율을 보장하지 않음; 주전 교대 강요 없음 |
| 육성 | 합의한 육성 배치 이행만 평가; CL 경기/훈련 성과는 근거 없음 |
| 만족도/구단 신뢰 | 각각 0~100, 새 관찰 60/50 |
| 주전·배치 위반 | 만족도 −4, 신뢰 −3 |
| 확인된 급여 체불 | 만족도 −6, 신뢰 −3 |
| 약속 이행/회복 | 만족도 +2, 신뢰 +1; 체불 정산 후 점진 회복 |
| 이동 관심 | 만족도 40 이하를 이동 검토 의향 및 판매 의사에 반영 |

새 평가 가능 Series가 없으면 출전 약속은 유예한다. 과거 낮은 선발 비율만으로 비시즌 내내 같은 불만을 누적하지 않는다. 관찰 유예와 표본 부족도 만족/불이행으로 단정하지 않는다. 급여 체불은 별도 확인 가능한 의무라 무경기 기간에도 평가한다. 육성 배치 이행과 미구현 CL 출전은 화면 사유로 구분한다.

선발 변경은 계약 역할을 바꾸지 않는다. 재계약/임대의 합의로 새 약속을 만들며 과거 기간과 구단별 신뢰는 남긴다. 이적한 새 구단의 만족도는 중립 관찰로 시작한다. 기존 선수 선호 평가의 보수·기회·전력·안정성·친숙함·지역 이동 부담에 `(대상 구단 신뢰−50)×12`를 더한다. 현재 구단 제안에는 `(현재 만족도−60)×8`, 다른 구단에는 `max(0,60−만족도)×8`을 더한다. 구조화된 평가값과 당시 정책/사유를 보존한다. UUID로 성향을 재추첨하지 않는다.

## 가치와 협상

기준 연봉은 저장된 선수의 역할별 12개 능력치 합 × 1,000 GAME_CREDITS다. `referenceSalary`가 조회 책임을 맡는다. 실제 지급 연봉이나 계약금, 잠재력·연령 추정으로 바꾸지 않는다.

남은 기간 계수는 0/6/12/24/36개월에서 0/0.5/1/1.6/2.1이다. 오늘부터 각 월수 뒤의 실제 날짜까지 일수를 앵커로 선형 보간하고 마지막에 정수 절삭한다. 계약 종료일을 포함하므로 `endDate+1`부터 남은 기간 0, 만료 후 가치는 0이다. 36개월 초과 계수는 2.1로 제한한다. 이는 초기 게임 설계값이며 실측 이적료 통계가 아니다.

검증 선수 Jiwoo의 기준 연봉은 **180,000**이다. 정확히 6/12/24/36개월이 남으면 추정 가치는 **90,000 / 180,000 / 288,000 / 378,000**이다. 실제 계약 연봉을 540,000으로 바꿔도 동일하다. 만료 뒤에는 0이다.

실제 브라우저의 2026-08-24에는 원계약 종료 2027-11-16을 포함해 **450일**이 남았다. 12개월 앵커는 365일, 24개월은 731일이므로 계수는 `1 + (450−365)/(731−365) × 0.6`이다. `180,000 × 계수`를 절삭한 **205,081**이 추정 가치, 110% 요구액의 절삭값 **225,589**가 판매 요구액이며 실제 제안/합의 이적료도 225,589였다. 새 연봉 243,000은 이 기준 가치를 계산하는 입력으로 쓰지 않았다.

판매 요구액은 추정 가치(임대는 참고 임대료)의 110%에 현재 선발 +25%p, 이동 관심 −15%p, 구단 체불 −10%p를 반영한다. 적격한 동포지션 대체자와 5인 선발을 확보하지 못하면 가격과 무관하게 거절한다. 구매 한도는 기존 주전 대비 전력 보강 130%, 포지션 공백 150%, 그 외 110%를 기준으로 확정 급여까지 지급 가능한 현금 여유와 비교한다. 합의 금액은 제안에 고정된다. 화면 추정 가치 갱신이 과거 합의 금액을 변경하지 않는다. 다른 구단의 내부 지불 상한/전체 AI 점수는 새 거래 조회에 노출하지 않는다.

## 거래·지급·임대

`CLUB_PENDING/CLUB_COUNTER → PLAYER_PENDING → AGREED → COMPLETED`로 진행하며 거절·철회·기한/수정 종료 사유를 남긴다. 구단 응답은 기본 2일 뒤, 선수 공통 결정은 7일 뒤, 수정은 최대 3라운드다. 적용일은 공통 결정 다음 날부터 7일 이내다. 같은 선수의 유효 경쟁 제안은 공통 결정일에 비교하고 동점은 구단 token 순으로 고정한다. 선수 조건의 기존 최소 보수와 수락 점수 검사를 유지하며 임대는 단기 안정성의 차이를 고려한 5,800점을 사용한다. 일반 유료 이적은 기존 6,200점 기준이다.

판매 구단 동의는 선수 동의를 대신하지 않는다. 사용자 구단의 판매/임대 또는 구매 동의와 대체 선발은 실제 UI 명령으로 받아야 한다. AI가 대신 동의하거나 사용자 선발을 조용히 바꾸지 않는다. 적용일에 원계약·미래 계약·임대·양쪽 예산·명부 용량·판매 선발을 다시 검사한다. 이전 조건을 소급 수정하지 않고 실패 거래를 명시적으로 종료한다.

유료 이적은 일시불 이적료, 양 구단 장부, 계약금, 이전 계약 `TRANSFERRED` 종료, 새 계약 활성화, 운영 소속·판매 선발 정리, 다른 제안 예약 해제를 하나의 Calendar 트랜잭션으로 저장한다. 일반 방출 보상금을 추가하지 않는다. 이전 계약의 체불은 이전 구단/원계약 identity에 남고 실제 판매 수입이 생기면 기존 체불 우선 정산 정책을 사용한다.

임대는 원계약의 team을 **법적 원소속**으로 유지한다. 기존 Membership.ownerTeam은 기존 명부·선발 소비자가 쓰는 **현재 운영/출전 팀**이며 임대 중에는 임대 구단이다. 새 Loan에 양 구단, 원계약, 기간, 반환 배치, 역할, 임대료와 급여 분담을 저장한다. 계약 검사를 없애지 않고 공통 자격/무결성 검사가 원계약과 임대 권한을 함께 확인한다.

임대는 28~366일, 원계약 종료일 이내다. 참고 임대료는 기준 연봉의 기간 일할액 ×20%, 기본 임대 구단 급여 분담 50%다. 0 임대료와 0~100% 분담도 합의할 수 있다. 급여 원금은 원계약 그대로이며 임대 구단 몫을 해당 연도의 누적 일할 정수 계산 차분으로 계산하고 나머지를 원소속이 낸다. 두 몫의 합은 원래 급여와 같다. 현금 부족 시 각 지급 구단에 자기 몫만 체불 원금으로 기록하고 이후 확정 수입으로 정산한다.

원소속은 임대 중에도 반환 자리를 예약하며, 임대 구단은 기간의 운영/포지션 용량과 분담 급여를 추가로 예약한다. 반환일은 종료일 다음 날이다. 임대 구단 선발에서 정리하고 원소속의 저장한 적법한 배치로 돌아가되 기존 주전을 밀어내지 않는다. 원계약도 끝났으면 같은 날짜 자연 만료/FA 경로를 따른다. 연도가 바뀌어도 원계약·임대·분담·체불이 이어진다. 이동 직후 28일, 임대 반환 뒤 28일 재거래 유예를 둔다.

### 날짜 순서

같은 날 확정 연간 배정/체불 정산 → 임대 반환(종료일까지 분담 정산) → 원계약 만료/정산 → 예약 계약 활성화 → 유료 거래/임대 적용 → 월말 급여 → 약속 평가 → 기존 제안 응답 → 월요일 AI 제안 → 기존 선수 결정/기한 → AI 선발 정비 순서다. 이적/임대 시작 전날까지 이전 지급 구조를 먼저 정산하고 적용일부터 새 지급 구조를 사용한다. Calendar 이벤트 점프도 중간 날짜를 같은 순서로 소비한다. GET/CPU 루프는 날짜를 진행시키지 않는다.

## AI와 저장 연결

56개 경쟁 구단의 공통 시장에서 기존 재계약/FA 후보를 먼저 검토하고, 보강 효과와 비용에 따라 유료 이적/임대 후보를 같은 스냅샷에서 수집한다. 구단당 한 주 최대 2건, 포지션별 적격 상위 3명으로 제한한다. 판매 불가능한 선발을 후보 제한 앞에서 걸러 실제 가능한 다음 후보를 고려한다. 유료 이적의 비용/한도가 맞지 않으면 원계약 급여 분담 임대를 비교한다. 후보 수집 동안 선수를 이동하거나 미확정 판매 수입을 쓰지 않는다. 모든 실제 AI 거래도 동일한 선수 동의·재정·명부 검사와 장부를 거친다. 해외/CL 게임을 만들지 않으며 출전 근거가 적다는 이유로 그 구단 선수를 불만 상태로 만들지 않는다.

V17은 `career_appearance_binding`, `career_opportunity_registration`을 추가한다. 기존 market JSON은 해시 검증 후 새 nullable management를 읽고, 명시적 recover에서 현재 게임 날짜부터 중립 약속을 초기화한다. 과거 Request 레코드의 직렬화 구조와 UUID payload hash는 유지한다. 별도 `TradeRequest`를 기존 market 명령 receipt 저장소에서 처리한다. GET마다 명부/정책을 재import하지 않는다.

POST `/api/v1/careers/{careerId}/market/trades`는 SUBMIT/COUNTER/ACCEPT/REJECT/WITHDRAW와 원본 연도·market revision·UUID·조건을 받는다. 같은 UUID/같은 조건은 원래 receipt로 복구하고 다른 조건은 충돌한다. 거래·명부 변경·경기 시작·완료는 Calendar 잠금을 먼저 취한다. League outbox도 Calendar 이후 outbox 잠금 순서를 지켜 새 금융/출전 경로와 잠금 역전을 만들지 않는다.

새 Career는 즉시 시작하고, 기존 Career는 recover 시 관찰을 시작한다. 미시작 Series는 현재 적법한 5명을 고정한다. 시작된 Series와 Draft/checkpoint/hash/receipt, 닫힌 국제 후보 집합은 다시 쓰지 않는다. 새 거래가 닫힌 국제 등록을 자동 확장하지 않는다. 다음 시즌은 현재 시장/명부 상태를 이월하고 출전 조회를 seasonYear별로 나눈다.

## 구현 위치와 사용자 효용

- `CareerManagementPolicy/State/Promises`: 수치 정책, 지속 이력, 약속 평가와 관계 점수.
- `CareerTrades`: 공통 거래·임대 상태 전이, AI 후보, 최종 양 구단 적용/반환.
- `CareerAppearanceStore`: 시작 시점 기회와 검증 완료의 멱등 반영.
- `CareerMarketEngine/Store`: 기존 계약·재정·Calendar/receipt 원자 경계 확장.
- `CareerRosterStore`, `LeagueRelationalStore`, `CareerCompetitionRelationalStore`: 등록·현재 자격·고정 입력·실제 완료 연결.
- `CareerTransferPanel`, `CareerPlayerPromises`: 실제 구매/판매/임대/응답/역제안 입력, 구단/선수 응답, 출전·만족도·원소속/임대 팀·복귀일 표시.
- `careerManagement.contract.ts`: 새 조회/명령과 보관된 원본 요청의 검증. 기존 공유 mutation gate/abort와 sessionStorage UUID 재시도를 사용한다.

관리자는 왜 주전 약속이 지켜지지 않았는지 확인하고 재계약에 실제 비용이 생기는지 판단할 수 있다. 원하는 선수를 자연 만료까지 기다리지 않고 합의한 이적료로 영입하거나, 원계약과 반환 자리를 유지한 임대로 단기 기회를 제공할 수 있다. 높은 제안 금액만으로 상대 선발/재정/선수 동의를 우회하지 않는다.

현재 집중 검증의 서로 다른 범위는 엔진 30건, 새 저장 통합 1건, 기존 marketCommands 1건, 실제 production Auto 대표 1건과 기존 마이그레이션/파일 재시작 1건이다. 뒤의 전체 회귀가 최종 트리 전체를 다시 검증한다.

실패는 다음처럼 분류하고 수정했다.

- 제품 결함: 대체 선발 null이 TreeMap 조회에서 NPE로 노출되던 경계는 명시적 자격 오류로 변경했다. 정상 유료 이적에서 이전 운영 소속이 남아 새 계약 활성화의 중복 소유 검사를 통과하지 못한 문제는 원자 적용 중 이전 운영 소속 정리 후 새 계약 활성화로 수정했다.
- 테스트 fixture: 최초 후보라도 AI가 거래 결정 전에 선발했으면 대체자 검사가 필요하다. 테스트는 해당 자격 검사를 우회하지 않고 유효한 대체자를 지정했다. T1 임대의 대체자를 HLE 소속 Gumayusi로 잘못 지정했던 테스트는 실제 T1의 Peyz로 교정했다. AI 후보 사례는 실제 임대 급여 여유까지 확보한 200,000과 첫 검토 포지션 TOP 공백으로 준비해 비용 때문에 아무 제안도 생기지 않는 잘못된 fixture를 수정했다. 생산 가격/선호 상수는 테스트 통과를 위해 튜닝하지 않았다.
- 환경: 초기 Gradle cache 쓰기 권한은 허용된 실행 경로로 해결했다. 집중 테스트와 bootRun을 동시에 시작해 같은 compileJava 출력이 경합한 35초/33초 실패는 두 실행을 끝내고 순차 실행하여 해결했다. 전체 회귀 실행 횟수에 포함하지 않는다.
- 프런트 fixture: 새 verifier의 미정의 fixture 변수/단언 사용을 기존 방식으로 교정했다. 기존 기대를 약화하지 않았다.
- 브라우저: 기존 CORS 허용 주소는 localhost:5173이므로 최초 127.0.0.1 origin 연결 실패를 허용 주소로 교정했다. 응답 소실 1건은 의도적 차단이다. 빠른 연속 날짜 진행 중 2건의 GET 503을 관찰했고 상태 새로고침에서 복구됐다. 거래/급여를 재적용한 것은 아니다. 임대 흐름은 각 조회를 기다리며 진행했다. 최종 화면은 임대 보낸 원계약 선수를 관리 구단 계약 목록에도 포함하며 정상 재조회 후 이전 시장 오류를 지운다. 파일 변경 감지가 없는 개발 서버 대신 최종 production build에서 수정된 목록을 재확인했다.

프런트 최종 `npm run career:verify`는 **63건 통과**, `npm run build`는 TypeScript/Vite 통과다. 최종 검증 서버용 빌드에는 `VITE_REAL_MATCH_API_BASE_URL=http://127.0.0.1:18185`만 지정했으며 소스의 기본 API 주소를 바꾸지 않았다. 마지막 Vite build 표시 시간은 **10.02초**다. 인접 Series/League/Draft의 공유 프런트 계약은 변경하지 않아 해당 verifier는 추가하지 않았다.

Playwright CLI의 실제 브라우저 조작은 `open/goto`, snapshot, fill/select/click, 응답 차단·검증용 run-code를 사용했다. 두 거래 흐름은 01:06~01:22 KST에 진행했으며 경기 완주는 브라우저에서 반복하지 않았다. 세부 로그는 무시되는 `backend/build/reports/career-management/`, 대표 최종 임대 화면은 `output/playwright/career-management-loan.png`다. 로그·이미지는 production 입력이나 정답 파일이 아니다.

### 정리

브라우저 세션과 별도 API/Vite/preview 서버는 종료했다. 원본 `선수정보/`, `능력치/`, `일정/`, 기존 `prompts/`를 수정하지 않았고 선행 `.gitignore` 변경을 보존했다. 검증 중 새로 관찰된 미추적 `선수정보.zip`과 별도 `AGENTS.md` 수정도 건드리지 않았다. `git diff --check`는 최종 통과했다. commit/push/배포는 수행하지 않는다.


## 제한과 다음 순서
