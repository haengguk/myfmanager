# Zeus·ShowMaker 사용자 승인 능력치 조정

2026-09-07 사용자가 승인한 12개 능력치 상향안을 기본 LCK 데이터에 반영했다.
추가 현실 경기 조사 결과가 아닌 게임 편집값이다. 선수 ID는 기존 identity 자료의
`player-zeus`, `player-showmaker`로 결합했다.

| 능력치 | Zeus 이전 → 적용 | ShowMaker 이전 → 적용 |
| --- | --- | --- |
| 조작 능력 | 19 → 20 | 18 → 19 |
| 상황 판단 | 18 → 18 | 18 → 19 |
| 전장 인식 | 17 → 18 | 18 → 19 |
| 위치 선정 | 17 → 18 | 18 → 19 |
| 교전 수행 | 19 → 20 | 18 → 19 |
| 안정성 | 16 → 18 | 18 → 18 |
| 미니언 수급 | 17 → 18 | 18 → 18 |
| 교환전 | 19 → 20 | 17 → 18 |
| 라인 관리 | 18 → 19 | 18 → 19 |
| 라인 압박 | 19 → 19 | 17 → 18 |
| 주도권 활용 | 17 → 18 | 18 → 19 |
| 사이드 운영 | 19 → 19 | 17 → 17 |
| 합계 | 215 → 225 | 213 → 222 |
| 참고 CA | 178 → 187 | 176 → 184 |

참고 CA는 `round(1 + (12개 평균 - 1) × 199 / 19)`로 계산했다.
기본 능력치 JSON의 스키마는 유지했다. 이후 사용자 요청으로 CA/PA 표시와 편집 기능을 같은 작업에 추가했다. [통합 구현 보고서](career-market-fixes-and-player-ability-editor-v1.md)를 참고한다.

## 적용과 파일

- `능력치/lck데이터/` 원본 JSON과 backend의 동일 리소스를 동기화했다.
- 로더와 기존 카탈로그/API 테스트의 정확한 SHA 기대값을 함께 갱신했다.
- LCK 50명 중 해당 2명의 능력치만 변경했다. 챔피언 숙련도와 PA는 별도 데이터다.
- 원본 검토표에 사용자 조정 근거와 변경 후 팀 평균을 기록하고 SHA 목록을 갱신했다.
- 리소스 버전/스키마와 최초 조사 날짜는 유지한다. 이번 편집 시점과 이전/이후 값은 이 문서로 구분한다.
- 사용자는 새 Career 전용 적용을 선택했다. 새 Career는 생성 시 새 능력치를 저장한다.
- 기존 Career의 directory와 시작한 Series의 고정 입력은 소급 변경하지 않는다. 현재 저장 검사는 생성 당시 카탈로그 해시와 현재 값을 비교하므로 이번 버전에서 기존 Career 로드는 차단된다. 기존 저장 호환은 별도 후속 작업이다.
- 기존 시장 공식이 능력치 합계를 사용하므로 새 Career의 기준 연봉은 Zeus 215,000 → 225,000, ShowMaker 213,000 → 222,000이다. 실제 제안 연봉과 이적료는 기존 계약 정책에 따라 결정된다.

새 LCK 리소스 SHA-256: `5c9fc7c86bf9b210cff5d1afb5e980fc9b64276751f0b88fb425db829deb9eb3`.

## 검증

변경 대상 2명/나머지 48명 보존, 원본·runtime 바이트 일치, 원본 SHA 목록 3건 일치를 확인했다.
기존 카탈로그·참조 API 집중 테스트 3 suites / 37 tests, 실패·오류·skip 0으로 통과했다(2분 57초).
계획된 전체 회귀에서 경기 실행부의 승인 리소스 묶음 해시와 Career 생성 API의 카탈로그 해시 기대값이 이전 데이터에 고정된 것을 발견했다. 개별 리소스 해시 갱신 외에 함께 변경해야 하는 연동 지점이다.
사용자가 전체 회귀 중단과 구현 범위 확대를 요청해 전체 실행을 중단했다. 묶음 해시와 Career API 기대값을 교정했고, 통합 작업에서 계약·편집 집중 39건 및 경기 입력·이주 대표 7건이 통과했다. 전체 회귀 완료로 주장하지 않는다. 추가한 편집 기능의 실제 브라우저 검증과 상세 비용은 통합 보고서에 기록했다.
